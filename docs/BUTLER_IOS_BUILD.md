# Build the Butler branch on your own iPhone (macOS/Xcode)

This guide fixes the three setup errors observed on the GitHub ZIP download: missing `ProviderCustomization.xcconfig`, missing FFmpeg/Rclone `.xcframework` products, and provisioning profiles for the upstream `com.openminis.app` entitlements.

## 1. Clone rather than use Download ZIP

```bash
cd ~/Downloads
git clone --recurse-submodules -b feat/ondevice-butler-foundation https://github.com/HiNesslio/OpenMinis.git OpenMinis-Butler
cd OpenMinis-Butler
```

GitHub ZIP archives do not supply the iSH and PRoot nested submodule source checkouts. They also do not contain locally built native frameworks. Please use a real clone rather than trying to manually copy placeholders into `deps/frameworks`.

## 2. Install native build prerequisites

Use a recent Xcode with the iOS SDK and Command Line Tools set to that Xcode. A physical ARM64 iPhone is strongly recommended for the first build.

```bash
xcode-select -p
xcodebuild -version
brew install ninja meson llvm libarchive pkg-config go
xcodebuild -downloadComponent MetalToolchain
```

Metal Toolchain is recommended for FFmpeg's complete hardware media filter set. If `brew` or Xcode are not installed, configure them first. The normal build also needs a working Python 3 interpreter.

## 3. Configure your own signing identity

**Personal Team / minimum-capability local build:**

```bash
python3 scripts/configure_ios_personal_dev.py --bundle-id com.example.minisbutlerdev
```

Replace `com.example.minisbutlerdev` with a unique reverse-DNS identifier you own. If you know your 10-character Apple Team ID, the script can set it on all targets:

```bash
python3 scripts/configure_ios_personal_dev.py --bundle-id com.example.minisbutlerdev --team ABCDE12345
```

### Fix "Signing requires a development team" after setup

If you previously ran `--bundle-id` **without** a `--team`, this is expected: the script leaves the team blank for you to select. Either choose your own Apple Team under **Signing & Capabilities** for `Minis`, `MinisShare`, `MinisFileProvider`, and `AgentWidgetExtension`, or assign it to every target without resetting your existing local project settings:

```bash
python3 scripts/configure_ios_personal_dev.py --set-team YOUR10CHARTEAMID
```

Replace `YOUR10CHARTEAMID` with the Team ID belonging to the Apple account already signed into Xcode. Do **not** use a random Team ID. You can inspect installed code signing certificates with `security find-identity -v -p codesigning`; if you have no certificate, open **Xcode > Settings > Accounts** to sign in and create/manage an Apple Development certificate. Keep **Automatically manage signing** enabled.

The command updates all target configurations while preserving the Bundle IDs and local Entitlements already generated by `--bundle-id`.

The script:

- Copies `src/ios/Configs/ProviderCustomization.xcconfig.example` to the locally ignored `ProviderCustomization.xcconfig` if absent. Empty provider values are fine for API-key sign-in.
- Saves an ignored backup of `project.pbxproj`, then rewrites all app, extension, test target Bundle IDs to unique identifiers.
- Points app and extension signing settings at one generated **empty** `PersonalDev.entitlements` file. This avoids asking an ordinary Personal Team profile for App Group, iCloud, APNs, HealthKit, HomeKit, NFC, and WeatherKit capabilities it may not support.
- Leaves the original tracked `.entitlements` files untouched. This is an **opt-in local build variant**, not the signed production configuration.

If you omit `--team`, open Xcode → select project → Signing & Capabilities and choose **Automatically manage signing**, then your own Team on each applicable target (`Minis`, `MinisShare`, `MinisFileProvider`, `AgentWidgetExtension`, and test targets if building tests).

**Important limitation:** the stripped-entitlement variant is for validating the basic Today, Calendar, Reminders, Living Memory and chat experience. App Group sharing/Share Extension, iCloud sync, HealthKit, HomeKit, WeatherKit, remote push and other privileged features **will not work**. Do not distribute this variant as the fully featured application.

If you have a paid Developer Program membership and need those original features, create your own App IDs, unique App Group and iCloud container within your team, align the runtime identifiers (for example `SharedContainerStore.appGroupID`), and enable only capabilities permitted by your profile. Do **not** reuse `group.com.openminis.app` or `iCloud.com.openminis.app`.

## 4. Build required native frameworks

```bash
bash scripts/prepare_ios_device_deps.sh
```

This runs the actual build scripts in order: LAME → FFmpeg (produces `FFmpeg.xcframework` and six `libav*.xcframework` bundles) → iSH → Alpine rootfs → Rclone (produces `Rclone.xcframework`). It also checks the outputs exist. Build failures should be fixed at the first failing command; **do not** create empty `.xcframework` directories to silence Xcode.

### Go JSON v2 / go-json-experiment build failure

If the Rclone build shows the following errors:

```text
undefined: json.SkipFunc
undefined: json.DiscardUnknownMembers
```

The repository currently pins `github.com/go-json-experiment/json` to the August 2025 prototype API. Go 1.27 uses a finalized JSON v2 implementation that removed these identifiers. The **Rclone build script now defaults `GOEXPERIMENT=nojsonv2`**, without changing `go.mod` or `go.sum`.

For a local checkout that hasn't pulled this fix yet, the equivalent one-off invocation is:

```bash
GOEXPERIMENT=nojsonv2 bash deps/build_rclone_ios.sh
```

To inspect the environment:

```bash
go version
go env GOEXPERIMENT GOTOOLCHAIN
```

If you previously set `GOEXPERIMENT=jsonv2` globally, unset it before running the updated script, or invoke the one-off command above. No `go clean -modcache`, library source modification, or unpinned module upgrade is needed for this workaround. The setting affects only the Rclone build process and its Go subprocesses. The Go 1.27 opt-out is transitional and should be revisited after upstream dependencies are upgraded and verified.

### If only Rclone.xcframework is missing

You can build just Rclone without re-running FFmpeg and iSH:

```bash
cd ~/Downloads/OpenMinis-Butler
go version
bash deps/build_rclone_ios.sh 2>&1 | tee rclone-build.log
ls -ld deps/frameworks/Rclone.xcframework
```

To make a shell pipeline return the true failure exit code of the build, run `set -o pipefail` first. If Rclone fails, **the first error in `rclone-build.log`** identifies whether the problem is the Go toolchain, Xcode SDK, dependency download, C compiler, or XCFramework packaging. The build creates both device and simulator slices. An empty placeholder folder will not work.

## 5. Build and run on iPhone

```bash
open src/ios/Minis.xcodeproj
```

In Xcode, choose scheme **Minis**, select your connected iPhone as destination, verify **Automatically manage signing** and your Apple Team, then Build/Run. The FFmpeg/iSH scripts above build device ARM64 libraries; a Simulator run requires separately building `--simulator` versions and is not the recommended first test.

## 6. Undo local signing changes

```bash
python3 scripts/configure_ios_personal_dev.py --reset
```

This restores the original `project.pbxproj` from its local backup and removes only the generated `PersonalDev.entitlements`. The local provider customization is intentionally preserved. Keep any API keys and local development files out of Git.

## Fix `clang: error: invalid linker name in argument '-fuse-ld=lld'`

This failure is from the **Linux ARM64 VDSO link step** in the pinned iSH Meson submodule. It may appear while building `libish.a`, `libish_emu.a`, and `libfakefs.a`, which depend on the VDSO target. Installing Homebrew `llvm` alone is insufficient because LLD is packaged separately.

```bash
cd ~/Downloads/OpenMinis-Butler
brew install lld
export PATH="$(brew --prefix lld)/bin:$PATH"
which ld.lld
ld.lld --version
set -o pipefail
bash deps/build_ish.sh 2>&1 | tee /tmp/minis-ish-build.log
```

The updated `deps/build_ish.sh` now checks for LLD and prepends a Homebrew LLD prefix when installed but not on PATH. It also performs a dry-run of the compiler's linker selection and fails with an actionable message **before** invoking Ninja. No need to alter the upstream iSH Git submodule, run `meson setup --wipe`, or rebuild FFmpeg/Rclone. An existing Meson build directory can be reused.

After the iSH build completes, verify:

```bash
ls -lh deps/libs/libish.a deps/libs/libish_emu.a deps/libs/libfakefs.a deps/libs/libish_aot.a
```

The `RootfsPatch.bundle` resource should also have been staged by `build_ish.sh`. If the Alpine ZIP is absent, run `bash deps/prepare_alpine_rootfs.sh` separately before rebuilding Xcode.

## Fix missing Alpine rootfs and RootfsPatch resources

Xcode copies both `deps/resources/alpine-rootfs.zip` and `deps/resources/RootfsPatch.bundle` into the app. Neither is committed to Git.

- `alpine-rootfs.zip` is generated by `deps/prepare_alpine_rootfs.sh` (downloads Alpine, builds/runs iSH fakefsify, and creates a zip).
- `RootfsPatch.bundle` is copied from the pinned iSH submodule by `deps/build_ish.sh`. The pinned `deps/ish/app/RootfsPatch.bundle` contains `manifest.plist`.

To recover **only** the missing patch bundle (without rebuilding any native libraries), copy it directly from the pinned iSH submodule:

```bash
cd ~/Downloads/OpenMinis-Butler
git submodule update --init --recursive
mkdir -p deps/resources
ditto deps/ish/app/RootfsPatch.bundle deps/resources/RootfsPatch.bundle
test -f deps/resources/RootfsPatch.bundle/manifest.plist && echo "RootfsPatch ready"
```

This is safe to repeat and does not require running the heavy iSH compiler. The `prepare_ios_device_deps.sh` helper now also stages this bundle **before** launching native builds, so an unrelated compilation failure will not leave the patch bundle absent.

If other iSH libraries or the Alpine archive are also missing, use the full recovery sequence:

```bash
cd ~/Downloads/OpenMinis-Butler
git pull --ff-only
git submodule update --init --recursive
bash deps/build_ish.sh
bash deps/prepare_alpine_rootfs.sh

ls -ld deps/resources/alpine-rootfs.zip deps/resources/RootfsPatch.bundle
unzip -tq deps/resources/alpine-rootfs.zip
ls -l deps/libs/{libish.a,libish_emu.a,libfakefs.a,libish_aot.a}
```

Never create empty placeholder files: the Linux sandbox needs an actual fakefs archive and the rootfs patch manifest. When all files exist, run **Product > Clean Build Folder** in Xcode and rebuild.

**`Command Ld failed with a nonzero exit code` requires separate diagnostics.** It is a generic linker failure, not evidence that a copy-resource step caused it. If it persists, inspect the expanded `Ld` invocation and the first preceding `ld:`, `Undefined symbols for architecture arm64`, or `library not found` message in the build log. Also check that the iSH archives listed above exist for the selected device architecture.

## If a build still fails

- `No such file ProviderCustomization.xcconfig`: rerun step 3 from a fresh clone.
- `No XCFramework found`: complete step 4, verify the specific `.xcframework` directory, and keep the *first* dependency build error.
- `App Group Identifier ... unavailable` / `profile doesn't include capability`: inspect the **local** `CODE_SIGN_ENTITLEMENTS` for each target. It should point to `Configs/PersonalDev.entitlements` for the minimal Personal Team build; do not keep the official original Entitlements in that mode.
- `Signing requires a development team`: choose your Apple Team for every signing target or rerun with `--team`.
- `Swift compilation error`: only after the above three setup groups are resolved, report the first actual Swift diagnostic separately (especially files under `ButlerOnDevice.swift` or `ButlerLocalNotifications.swift`).

See [upstream BUILDING.md](../BUILDING.md) for the detailed device/simulator toolchain requirements.
